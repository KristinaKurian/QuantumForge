# Task 1 — Исследование моделей и инфраструктуры

## 1. Контекст и критерии выбора

QuantumForge Software планирует внутреннего RAG-бота для поиска по корпоративной базе знаний:

- около 18 000 Markdown/MDX-файлов;
- около 3 000 страниц Confluence;
- около 250 PDF-документов;
- прирост около 400 страниц в месяц.

Ключевые критерии: качество retrieval и generation, стоимость, конфиденциальность, скорость, сложность эксплуатации, масштабируемость и совместимость с AWS-инфраструктурой.

Часть документов может содержать чувствительные данные, поэтому доступ к контексту должен проверяться до передачи фрагментов в LLM.

## 2. LLM

| Критерий | Local Qwen3-8B | OpenAI | YandexGPT |
|---|---|---|---|
| Качество | Хорошее при качественном retrieval | Высокое | Хорошее, особенно для русского |
| Инфраструктура | Нужен локальный inference | API | API |
| Стоимость | Сервер/GPU, без оплаты за токены | Оплата за токены | Оплата за токены |
| Конфиденциальность | Максимальный контроль | Зависит от политики передачи данных | Зависит от политики передачи данных |
| Масштабирование | Самостоятельное | На стороне провайдера | На стороне провайдера |
| Vendor lock-in | Низкий | Средний/высокий | Средний/высокий |

Для задач 2–5 выбран **локальный Qwen3-8B через Ollama**: он позволяет показать полный RAG-пайплайн без внешнего API и не передавать учебную базу знаний стороннему провайдеру.

Для production целесообразна гибридная схема: разрешённые данные могут обрабатываться cloud LLM, а чувствительные — локальной моделью.

## 3. Embeddings

Сравниваются локальные Sentence-Transformers и OpenAI Embeddings.

Для реализации выбрана:

```text
sentence-transformers/multi-qa-mpnet-base-cos-v1
```

| Критерий | Sentence-Transformers | OpenAI Embeddings |
|---|---|---|
| Выполнение | Локально | Внешний API |
| API cost | Нет | За токены |
| Конфиденциальность | Данные остаются локально | Текст отправляется провайдеру |
| Инфраструктура | CPU/GPU | Минимальная |
| Vendor lock-in | Низкий | Есть |

Модель подходит для semantic search: короткий пользовательский вопрос сравнивается с более длинными фрагментами документации.

Для облачных embeddings стоимость первичной индексации также невелика. Например, при 20 млн токенов и условной цене `$0.02 / 1M tokens`:

```text
20 × $0.02 = $0.40
```

Фактическое качество модели следует измерять на реальных вопросах с помощью Recall@K, MRR, Hit Rate@K и nDCG@K.

## 4. Vector store

| Критерий | FAISS | ChromaDB |
|---|---|---|
| Тип | Векторный индекс / библиотека | Vector database |
| Metadata | Отдельно | Встроено |
| Metadata filtering | Реализуется приложением | Поддерживается |
| Persistence | Контролируется приложением | Встроено |
| Отдельный сервис | Не нужен | Возможен |
| Overhead | Минимальный | Выше |
| Подходит для MVP | Да | Да |

Для проектной работы выбран **FAISS**: он прост, не требует отдельного сервиса и достаточен для текущего объёма данных.

FAISS не является безусловным production-выбором. При сложных ACL, metadata filtering, большом числе коллекций или независимом lifecycle индекса стоит перейти на полноценную vector database.

## 5. Серверная конфигурация

### Облачная LLM

| Ресурс | Рекомендация |
|---|---|
| CPU | 4–8 vCPU |
| RAM | 16–32 GB |
| GPU | Не требуется |
| SSD | 100 GB+ |
| ОС | Linux |
| Запуск | Docker / Kubernetes |

### Локальная LLM

| Ресурс | Рекомендация |
|---|---|
| CPU | 16 vCPU |
| RAM | 64 GB |
| GPU | NVIDIA GPU с 24 GB VRAM |
| SSD | 200 GB NVMe |
| ОС | Linux |
| Serving | Ollama / vLLM / аналог |
| Запуск | Docker / Kubernetes |

Для 7–8B quantized-модели 24 GB VRAM дают разумный запас; для более крупных моделей и высокой параллельности нужен больший объём памяти.

## 6. Варианты архитектуры

| Вариант | LLM | Embeddings | Vector store | Основной сценарий |
|---|---|---|---|---|
| A. Cloud | OpenAI | OpenAI | FAISS | Самый быстрый старт |
| B. Local | Qwen3-8B | Sentence-Transformers | FAISS | Локальный MVP и чувствительные данные |
| C. Yandex | YandexGPT | Local / cloud | FAISS / ChromaDB | Yandex Cloud |
| D. Hybrid | Cloud + local Qwen | Sentence-Transformers | FAISS / vector DB | Production |

В задачах 2–5 реализован **вариант B**.

## 7. Итоговая архитектура

Учебный MVP:

```text
Question
   ↓
Sentence-Transformers
   ↓
FAISS
   ↓
Top-K + relevance threshold
   ↓
Qwen3-8B / Ollama
   ↓
Answer + sources
```

Для production дополнительно необходимы ACL/RBAC до retrieval, classification чувствительности, audit logs, мониторинг и маршрутизация между cloud/local LLM.

![Целевая архитектура RAG](images/rag-target-architecture.png)

Выбранные компоненты слабо связаны между собой: embedding-модель, FAISS и LLM могут заменяться независимо без изменения общей логики RAG.
